# 内置题库设计与数据来源

## 一句话结论

`app/assets/quiz.db` 里的**题目不是从任何题库抄来的**，而是把开源仓库
[RedSamerai/learning-content](https://github.com/RedSamerai/learning-content)
的**全部知识点纲目**导入 SQLite 后，由 `tools/quizbank/build_bank.py`
参数化生成的；正确答案由纲目数据本身或程序计算确定。

上游仓库只有「年级段 / 学科 / 章节 / 知识点」这类纲目字段，
**没有题目、选项、答案**（实测 4,026 个 JSON 中大部分 `description` / `example` /
`explanation` 为空）。因此不存在「把现成真题搬进来」这回事。

## 全量导入口径

| 来源 | 内容 |
| --- | --- |
| `knowledge_graph_complete.json` | 总图谱（4,118 条） |
| `knowledge_graph_backup_4375.json` | 备份总图谱（4,375 条，含九年级全一册） |
| `output/<年级段>/<学科>/*.json` | 逐知识点文件（4,024 个） |

脚本读取以上 **4,026 个文件**，按
`(年级段, 学科, 章节, 知识点)` 去重，逐字段保留信息最全的一份，
合并出 **4,319 条**知识点，覆盖 **19 个学科 / 21 个年级段**
（幼儿园、幼小衔接、小学一至六年级上下、初中七至九年级上下及全一册）。
原始 `id / description / example / explanation / key_points / content / 来源文件`
全部存进 `knowledge` 表，不做裁剪。

## 表结构

| 表 | 用途 |
| --- | --- |
| `knowledge` | 全量纲目，保留上游全部非空字段与来源路径 |
| `chapters` | 兼容旧版 App 的精简纲目视图 |
| `questions` | 四选一题：`grade / grade_label / subject / subject_group / chapter / topic / text / opt_a..opt_d / answer_index / explain / source / qhash` |
| `meta` | 版本戳、题数、知识点数、学科数、年级段数、来源与授权说明 |

`subject_group` 把 19 个学科归到 `math / chinese / english / other`，
使「仅三科」与「全学科」两种出题模式都能用索引查询。

## 题目生成

| 类型 | 数量 | 正确答案来源 |
| --- | ---: | --- |
| 纲目题 | 4,319 | 三种题型轮换，答案全部由纲目字段确定：① 该年级段某学科的知识点辨识；② 知识点所属学科；③ 知识点所属年级段 |
| 程序出题 | 810 | 1-9 年级 × 数/语/英各 30 道：数学为实际计算的加减乘除、周长、质数合数、百分数；语文为古诗/反义词/成语；英语为词汇/句型。答案由 Python 计算或固定词表给出 |

干扰项取自同学科不同章节、不同学科或不同年级段的真实知识点，
保证 4 个选项互异且正确答案唯一；题干超过 24 字会截断，
App 端 `QuizTextSizer` 还会按长度自适应字号。

> **质量说明**：纲目题偏「知识点辨识」，不是教材同步真题，也不是教辅题。
> 它的作用是打断连续观看、让孩子回忆一下学过什么；如果你要真题，
> 请自行准备有授权的数据，按同一 `questions` 表结构导入即可。

## 校验

`tools/quizbank/verify.py` 独立于构建脚本复跑以下检查：

1. 表结构与 `meta` 行数一致；
2. 每题 4 个非空且互异选项、`answer_index ∈ [0,3]`、题干与解析非空；
3. 复现 App 端 `QuizEngine.Question.fromBank()` 的合法性规则；
4. 9 个年级 × 3 科 × 40 次 + 全学科 360 次随机抽题，共 1,440 次，取不到即失败；
5. 纯算式题用 Python 重算答案索引；
6. 知识点覆盖：学科数与年级段数下限；
7. 篡改检测：翻转一个字节后 SHA-256 必须变化。

## 重建与升级

```bash
python3 tools/quizbank/build_bank.py \
    --lc /path/to/learning-content \
    --out app/assets/quiz.db \
    --stats docs/BANK_STATS.md --seed 20261104
python3 tools/quizbank/verify.py app/assets/quiz.db
```

脚本同时写出 `app/assets/quiz.db.version`。App 启动时把该版本戳与本地库中
`meta.version` 比对，不一致才复制新库（写 `.tmp` → `fsync` → 校验可读 →
`renameTo` 原子替换），避免重复复制 4.5 MB 和半截数据库。

## 许可证边界

上游 `learning-content` 仓库**未附 LICENSE**。本仓库的 MIT 许可证**只覆盖代码**，
不包含 `app/assets/quiz.db` 中的纲目数据；该数据仅供个人非商业学习使用。
仓库与 APK 中不含任何火花 K12 / 付费接口 / 爬取所得的真题文本。
如需公开再分发，请先确认上游授权状态或换成自己有权利使用的数据源。

## 错题库（v6）与教材版本边界

错题不写回 `quiz.db`（它是只读 assets 副本），而是存在应用私有目录的
`pohw_wrong.db`：表 `wrong` 保存题面快照、四个选项、正确答案下标、解析、
最后一次选错的选项、累计错误次数、时间、年级/学科/教材版本/知识点。
题目以 `qkey = SHA-256(长度前缀(学科 + 正确答案下标 + 题干 + 四个选项))` 去重，
重复答错累加次数；写入在单线程后台队列且包在事务里完成，控制台用缓存计数显示，
不每秒查询 SQLite。`onUpgrade()` 采用非破坏式迁移，不会 DROP 掉家长积累的错题；
列表最多展示最近 500 条，标题显示的是真实总数。

**教材版本说明**：上游 `learning-content` 只有纲目（年级段 / 学科 / 章节 / 知识点），
没有出版社或教材版本字段，因此 `questions` 表也没有 `edition` 列。
v6 的分学科教材版本设置会：

1. 按学科筛选可选的在线题包（`pack.json` 的 `edition` 字段）；
2. 显示在答题页元信息里；
3. 作为标签写入错题库记录。

它**不会**改变内置离线题库的抽题结果。若需要真正按教材版本出题，
必须自行准备带 `edition` 字段的题包并配置在线源，或重建 `quiz.db`。

**v1.0.0 修正（在线题包空转）**：开发期 v6.0.0 的 `QuizEngine.next()` 在注入内置 DB 后
会立刻 `return db.random(...)`，导致按学科版本筛出来的在线题包几乎永远抽不到。
现在 `next()` 按 `BANK_RATIO` 概率在「在线题包 / 内置 DB」之间混合，两者都为空时
才回退参数化生成器；`Subjects.OTHER` 的题包也会在全学科模式下被抽中。
在线题包的 `subject` 字段除数学/语文/英语外一律归入「其他学科」。

**v1.0.1 / versionCode 15 修正（配比被旁路）**：此前 `allSubjects=true` 会让 `QuizDb.random()`
退化为 `WHERE grade=?` 的 gradeWide 抽样，配比完全不决定题目学科，其他学科占比由题库题量决定。
现在改为四槽权重（默认 5:3:2:2）+ 两条 SQL 池：三科按 `grade + subject`，其他学科按
`grade + subject NOT IN (数/语/英)`；`q.subject` 由题目真实学科反推，错题库不再串科。
`tests/bank_distribution_check.py` 会用源码里的真实 SQL 复验池隔离与配比分布。

**复审加固（同 code15 定版）**：兜底改为池保持 —— 先只放宽年级
（`POOL_CORE_ALL` / `POOL_OTHER_ALL`），最后才全库，避免空池时静默退回跨科抽样；
随机 OFFSET 用 `MAX(1, (SELECT COUNT(*) ...))`，空池返回 0 行而不是抛
`datatype mismatch` 被 catch 吞掉；`QuizDb.hasOtherQuestions()` 在其他学科池为空时
让第 4 槽直接失效，不会选中 OTHER 后只能回退成数学题。分布校验脚本先去注释、
再从 `QuizDb.java` 的 `POOL_*` 命名常量取同源 SQL，并新增 `FALLBACK_POOL_OK`：
模拟三年级英语池和其他学科池都为空，验证兜底仍然保持学科约束、不串池。

## 题库粒度与学习进度：现状与可选路径（只读调研，尚未实现）

> 2026-11-05 的一次**只读调研**，用于回答「三年级上学期刚开学 1–2 个月，选 3 年级却会抽到整学年甚至超纲题」这一困境。
> **当前 APP 未实现任何学期 / 单元过滤**，`QuizDb.random()` 的 WHERE 仍只有 `grade + subject`。
> 下列方案只是候选，等确认后再动代码。

### 题库里到底有什么

`app/assets/quiz.db`（`pohw-2026.11.04-full-s20261104`，5,129 题，4 张表：`questions` / `knowledge` / `chapters` / `meta`）。
`questions` 共 17 列：`id, grade, grade_label, term, subject, subject_group, chapter, topic, text, opt_a..opt_d, answer_index, explain, source, qhash`。

| 字段 | 能否限进度 | 实情 |
| --- | --- | --- |
| `grade` | ✅ 已用 | 1–9（另有 0 = 幼儿园 / 幼小衔接） |
| `term` | ✅ **现成可用，目前没用** | `上` / `下` / `全` / `''`。4,319 道纲目题里 1–9 年级都有上下册（三年级上 196 题、三年级下 148 题），九年级另有「全一册」201 题 |
| `grade_label` | 辅助 | `三年级上` / `三年级下` / `一年级`（无学期） |
| `chapter` | ❌ 不是教材单元 | 是**题型 / 能力分类**：几何 / 应用 / 概念 / 综合 / 计算 / 语法 / 词汇 / 阅读…，英语里还夹着 `Unit 1 School` 这类真单元名；`综合练习` 810 条 |
| `topic` | ⚠️ 间接可用 | 形如 `几何：时分秒`，冒号后面是**教材单元名**。三年级上数学可提取 8 个：时分秒、万以内的加法和减法、测量、倍的认识、多位数乘一位数、长方形和正方形、分数的初步认识、数学广角 —— 接近人教版三上单元，但**没有序号、没有教材版本、没有教学顺序**，且同一批单元被复制到每个 `chapter` 前缀下 |
| 教材版本 / 单元序号 / 难度 | ❌ 不存在 | 17 列里没有 `edition` / `unit_index` / `unit_no` / `difficulty`。分学科教材版本只用于在线题包筛选与题面标注，不影响离线抽题 |

结论：**上下学期能直接做**（字段现成、数据齐全）；**「截止到第几单元」不能直接做**，只能靠 `topic` 里的单元名间接实现，且必须补一份外部教材顺序表或让家长手勾。

### 两个必须一起看的质量事实

1. **5,129 题 = 4,319「纲目题」+ 810「程序出题」**。纲目题是「知识点「几何：倍的认识」属于哪个学科？」「下列哪个是要掌握的知识点？」这类**纲目定位题**，不是学科能力题。
2. **810 道程序出题没有学期和单元**（`term=''`、`chapter='综合练习'`，每年级每科 30 道），且三年级样本里混进了「下面哪个数是质数？」「40 的 50% 是多少？」这类明显超纲题。
3. `QuizEngine.next()` 的优先级是「在线题包(60%) → 内置 SQLite → 在线题包兜底 → 参数化生成器」。因为 `db` 几乎总有题，**按年级分档的参数化生成器（`mathG1..mathG6`，三年级 10 类题型）基本用不上**，而它们才是天然不超纲、无限量的能力题。

所以「孩子完全不会做」是**两层原因**：抽题范围按整学年（甚至超纲），且主力题目是纲目定位题。只做学期过滤只解决第一层的一半。

### 可选路径（待拍板，均未实现）

| 方案 | 做什么 | 代价 | 能解决到哪一步 |
| --- | --- | --- | --- |
| **A 学期维度** | 设置页加「上册 / 下册 / 全学年」（默认全学年，兼容覆盖安装）；`QuizDb.random()` WHERE 加 `AND term=?`；`term=''` 的 810 道程序出题做成「是否含综合练习」开关 | 低：1 个 SP 键 + 1 行 UI + 1 个 SQL 条件 + 契约 / 单测 / 分布回归扩展 | 只分上下册；三年级上约 196 题（数学 43 题），够弹，但解决不了「刚开学只学 2 单元」 |
| **B 学期 + 单元进度** | 在 A 上加「已学到第 N 单元」，按有序单元名单过滤 `topic`；**必须新增 `assets/syllabus.json`** 人工维护「教材版本 × 年级 × 学期 × 学科 → 有序单元名数组」 | 中高：题库没有顺序 / 版本，需补外部进度表并和 `topic` 对名；还要处理「选中单元题太少」的兜底 | 真正贴合「开学 1–2 个月」；建议先只做 1–6 年级数 / 语 / 英人教版试点 |
| **C 能力题优先** | 把 `mathG1..mathG6` 提升为主来源，家长选「能力题优先 / 纲目题 / 混合」；三年级 10 类题型（万以内加减法、多位数乘一位数、分数初步、周长、单位换算…）可按「已学题型」白名单开关 | 中：改 `QuizEngine.next()` 优先级 + 题型白名单 + UI；语文 / 英语的参数化题较薄 | 治「题目类型不对」这一层，不依赖题库标签、不需要教材顺序表 |
| **D 重做题库标签** | 给 5,129 题补 `edition / unit_index / unit_name / difficulty`，剔除三年级质数 / 百分数，纲目定位题降级为知识卡 | 最高；learning-content 本身没有单元顺序，仍需人工或 LLM 标注 | 治本但周期长 |

**推荐**：先做 **A + C**（学期过滤 + 能力题优先），一次解决「范围太大」和「题目不会做」；若确认必须精确到「课本第几单元」，再补 B 的进度表。B 另有可选增强：按当前日期估算开学周数给一个默认单元，但地区 / 版本差异大，只能作为家长可覆盖的默认值。

**所有方案共通约束**：选中范围为空时，兜底只能**逐级放宽学期 / 单元、不得放宽学科**，否则会重新出现串科、超纲题；实现时需把现有 `POOL_*` 三层池保持兜底扩展成四层，并同步扩展 `tests/bank_distribution_check.py` 与负向变异套件。
